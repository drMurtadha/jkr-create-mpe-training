# Panduan Peserta Langkah demi Langkah — Modul 3

Panduan ini merangkumi aktiviti GitHub pada Modul 3A, diikuti analisis data dan pengurusan rekod teknikal.

## Hasil akhir

- Satu commit dan pull request bagi setiap peserta;
- Satu set data latihan yang telah disemak;
- Satu jadual atau visual ringkasan;
- Tiga dapatan yang dapat dijejak kepada data;
- Satu checklist audit rekod teknikal.

## Bahagian A — GitHub asas dan kerja berpasukan, 30 minit

### Langkah 1 — Sediakan tiga kumpulan, 5 minit

1. Bentuk tiga kumpulan daripada sembilan peserta.
2. Pilih seorang ketua projek bagi setiap kumpulan.
3. Ketua membuka atau mencipta repositori latihan.
4. Ketua menjemput ahli sebagai collaborator.

**Selesai apabila:** semua ahli dapat membuka repositori kumpulan.

### Langkah 2 — Cipta branch dan perubahan kecil, 8 minit

1. Setiap ahli mencipta branch dengan nama sendiri atau tugasan.
2. Buka satu fail latihan yang ditetapkan.
3. Buat satu perubahan kecil dan jelas.
4. Semak perbezaan sebelum menyimpan.

**Selesai apabila:** perubahan hanya terdapat pada branch ahli dan tidak menyentuh `main`.

### Langkah 3 — Commit, push dan pull request, 10 minit

1. Tulis mesej commit yang menerangkan tujuan perubahan.
2. Push branch ke GitHub.
3. Buka pull request ke `main`.
4. Terangkan perubahan dan cara menyemaknya.

**Selesai apabila:** setiap ahli mempunyai satu pull request yang boleh dilihat ketua.

### Langkah 4 — Semak dan merge, 7 minit

1. Ketua menyemak tab **Files changed**.
2. Ketua meminta pembetulan jika perlu.
3. Ahli membaiki perubahan pada branch yang sama.
4. Ketua merge pull request yang lengkap.
5. Semua ahli mengesahkan perubahan pada `main`.

**Bukti serahan:** pautan repositori, ID commit dan nombor pull request.

## Bahagian B — Analisis data sistematik

### Langkah 5 — Tetapkan soalan analisis, 5 minit

1. Buka set data latihan.
2. Pilih satu soalan yang boleh dijawab oleh medan tersedia.
3. Nyatakan unit, tempoh dan kumpulan perbandingan.

**Selesai apabila:** soalan tidak meminta maklumat yang tiada dalam data.

### Langkah 6 — Fahami dan semak kualiti data, 10 minit

1. Semak nama medan, jenis data dan unit.
2. Cari nilai kosong, pendua, format tidak seragam dan nilai luar julat.
3. Simpan salinan asal tanpa perubahan.
4. Catat setiap pembetulan dalam log perubahan.

**Selesai apabila:** kumpulan boleh menerangkan batas data dan perubahan yang dibuat.

### Langkah 7 — Analisis dan visualkan, 12 minit

1. Pilih ukuran ringkas seperti jumlah, purata, median atau perubahan.
2. Jalankan pengiraan pada data yang telah disemak.
3. Hasilkan satu jadual atau carta yang sesuai.
4. Semak label, unit dan skala.

**Selesai apabila:** angka pada visual boleh dikira semula daripada data.

### Langkah 8 — Tulis dan sahkan dapatan, 8 minit

1. Tulis tiga dapatan berdasarkan visual.
2. Bezakan fakta, tafsiran dan cadangan.
3. Elakkan dakwaan sebab-akibat yang tidak disokong.
4. Minta ahli lain menyemak setiap dapatan.

**Selesai apabila:** setiap dapatan merujuk angka, tempoh atau kategori yang jelas.

## Bahagian C — Pengurusan rekod teknikal

### Langkah 9 — Audit rekod, 10 minit

1. Buka rekod teknikal rekaan.
2. Semak ID, tarikh, aset, keputusan, status dan pegawai pengesah.
3. Tandakan medan kosong, konflik dan rekod pendua.
4. Catat tindakan pembetulan tanpa memadam rekod asal.

**Selesai apabila:** setiap isu mempunyai pemilik tindakan dan status.

### Langkah 10 — Sediakan jejak audit, 5 minit

1. Catat sumber rekod.
2. Catat siapa yang mengubah, menyemak dan meluluskan.
3. Simpan nombor versi dan masa semakan.
4. Bentangkan satu dapatan dan satu risiko data.

**Bukti serahan:** fail analisis, visual, tiga dapatan dan checklist audit rekod.

## Jika tersekat

- Gunakan tangkap layar GitHub dalam panduan GitHub asas.
- Gunakan fail data rekaan yang disediakan dalam portal.
- Jika pull request belum boleh di-merge, serahkan pautannya sebagai bukti latihan.
